# Documentation Sweep — 2026-07-25

Audit of `docs/` against the newly written
[`AVC_Competition_Overview.md`](AVC_Competition_Overview.md), performed while adding the
Neutron NPU research folder.

**Headline:** the docs are in better shape than expected. Technical research notes are
accurate and internally consistent. The single real gap was **the competition itself was
never written down** — now fixed. One duplicate file needs a decision from the owner.

## Findings

### 1. Competition context was entirely missing — FIXED

No document described the event, the track, the chassis, the student-facing constraints,
or the 41 ms budget. Every plan silently assumed all of it. Grepping for
`competition|track|student|race|55cm|FIT` returned only incidental mentions inside
hardware notes.

**Resolution:** `AVC_Competition_Overview.md` written. It is now the context doc the plans
should be read against.

### 2. Duplicate file — RESOLVED

```
docs/AVC_Camera_Interface_Research.md
docs/research/AVC_Camera_Interface_Research.md
```

**Byte-identical** (md5 `63b8d5446e6b7c2f9910eb38f2332e1b`), both introduced by commit
`028b5ce`, and — importantly — **both currently show as modified in the working tree.**
That is active divergence risk: two copies being edited with no mechanism keeping them in
sync.

`AGENTS.md` designates `docs/research` as the durable reference location, so the root-level
copy was the leftover.

**Resolved:** both copies were committed first (so nothing was lost), re-diffed to confirm
they were still byte-identical, then `docs/AVC_Camera_Interface_Research.md` was deleted.
Every inbound reference — from `AVC_LVDS_Adapter.md`, `FlexIO_Camera_Test_Plan.md`,
`N947_USB_Host_Assessment.md`, `RT_Crossover_Camera_Platform.md`, `CoolFlux/README.md`,
and `AVC_Competition_Overview.md` — is relative and already resolved to the `research/`
copy, so no link needed fixing.

`docs/` root now holds no `.md` files at all; everything lives under `research/`, `plans/`,
`examples/`, or a topic folder.

### 3. Slightly stale figures — annotated in place

`FlexIO_Camera_Test_Plan.md:9` (dated 2026-06-17):

> **SRAM ~480 KB** -> full QVGA RGB565 frame (320x240x2 = 153.6 KB) fits with room to spare

Two small drifts: the shipped configuration is **320×200**, not QVGA 320×240; and the
linker actually defines 384 + 96 + 32 + 4 = 516 KB of regions
(`avc_core0_Debug_memory.ld`). Neither invalidates the point being made — it is a capacity
argument and the capacity claim still holds.

**Resolved by annotation, not rewrite.** A dated note was appended below the original line
correcting both figures and pointing at `AVC_Competition_Overview.md` §7. The original text
stays as written, because it is a dated test plan and silently rewriting its "verified
hardware facts" would destroy the record of what was believed on 2026-06-17.

### 4. Frame-rate claims are consistent and evidence-backed — good

`~24 FPS` appears across several docs and is corroborated by measurement in
`AVC_USB_Debug_Display_Current_State.md`: `23.43 FPS` over a 60 s native receiver run and
`23.39 FPS` from RTT telemetry. The overview uses `~24 FPS` and cites the EZH as the
limiter, matching `AVC_LVDS_Adapter.md:124` which independently concludes the cable is no
longer the cap.

### 5. `docs/car_chassis/` was untracked and unreferenced — now cited

A 19 MB static dump of the Hiwonder product page (`web/*.html`, `dimensions.png`, 138
files) sat untracked in `docs/` with nothing pointing at it. It turns out to contain
**vendor specifications that resolve an open item in an active plan**:

- Motor `JGB37-520R90-12`, encoder **AB dual-phase, 11 lines**, so
  `counts/wheel-rev = gear_ratio × 11 × 4 (quadrature)`.
- Hiwonder support states 1:30 → **1320 counts/wheel-rev**, corroborated by a customer's
  measurement over ten hand rotations on both motors.
- **But the spec table on the same page says 1:90**, which would give 3960. The vendor
  contradicts itself.
- Also recovered: **40° max steering angle, 0.173 m minimum turning radius**, full motor
  and servo electrical specs, chassis alloy.

This bears directly on `CONFIG__MOTOR_ENCODER_COUNTS_PER_WHEEL_REV`, which was `0` at the
time of this sweep.

> **Resolved later the same day.** Measured on the car: 13188 counts over exactly 10
> hand-turned revolutions = **1320**, backing the support answer's 1:30 over the spec
> table's 1:90. The constant is now set. See
> [`AVC_Motor_Encoder_QDC_Research.md`](AVC_Motor_Encoder_QDC_Research.md).

**Resolved:** the folder is committed, and `docs/car_chassis/README.md` now extracts every
usable spec (chassis, motor, servo, encoder, support links) so the 19 MB dump never has to
be opened to answer a question. The dump is the backup; the README is the interface.

### 6. Cross-references added

`AGENTS.md` now points at the competition overview as the first thing to read, ahead of the
FlexIO camera material. Previously an agent or new contributor started at
`FlexIO_Camera_Test_Plan.md` with no idea what the project was for.
