# Log: flexio-low-rate-capture

Implemented and tested the first real FlexIO plus eDMA camera data movement
backend.

Firmware changes:

- Switched the active camera backend to `FLEXIO_EDMA`.
- Configured `P4_12..P4_19` as `FLEXIO0_D20..D27` camera data inputs.
- Configured `P4_20/FLEXIO0_D28` as the FlexIO timer PCLK input.
- Configured `P4_21/FLEXIO0_D29` as the FlexIO HREF gate.
- Kept `P4_22` as the GPIO VSYNC interrupt that starts each DMA capture.
- Used DMA1 channel 0 with FlexIO shifter 0 request 61 so the existing LCD SPI
  DMA0 use is not disturbed.
- Aligned the existing camera frame buffers to the 32-byte eDMA minor transfer
  size.

Hardware state:

Camera sync remains wired as:

- `PCLK -> P4_20`
- `HSYNC/HREF -> P4_21`
- `VSYNC -> P4_22`

The camera data lines are disconnected for this test, with pulldown termination
holding the data bus low. Expected pixel data is therefore RGB565 black
(`0x0000`).

Verification:

- `.\build_cmake.ps1` completed successfully.
- `.\flash.ps1 -CMake -JLinkPath 'C:\Program Files\SEGGER\JLink_V954\JLink.exe'`
  programmed the board with VTref at 3.300 V.
- `.\rtt.ps1 -CMake -Reset -Seconds 15 -JLinkDllPath 'C:\Program Files\SEGGER\JLink_V954\JLink_x64.dll'`
  showed stable `cam_dma` reporting.

Representative RTT output:

- `cam_dma done=324(+30) start=325 p4_vs=325(+30)`
- `timeout=0 submit_err=0 cb_err=0`
- `sample_nz=0 first=0000,0000,0000,0000`

Result:

The FlexIO timer, HREF/PCLK gating, FlexIO shifter DMA request, DMA1 transfer,
frame-buffer destination, and existing AVC frame handoff are all working for a
pulled-low black-frame capture. The next validation is controlled nonzero data:
tie one data bit high or restore a small subset of real camera data lines to
prove bit position, byte order, and RGB565 packing before wiring the full bus.
