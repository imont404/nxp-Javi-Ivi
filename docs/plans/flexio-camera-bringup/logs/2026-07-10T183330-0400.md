# Log: Rev B VSYNC Timing Note

Documented that the current Port 4 wiring is validation hardware for deciding
whether the FlexIO camera interface should be carried into the Rev B FRDM shield
for the NXP Cup car.

No current I/O wiring changed. The active bring-up map remains:

- `D0-D7 -> P4_12..P4_19 / FLEXIO0_D20..D27`
- `PCLK -> P4_20 / FLEXIO0_D28`
- `HSYNC/HREF -> P4_21 / FLEXIO0_D29`
- `VSYNC -> P4_22 / GPIO IRQ frame-start trigger`

The new note records that `P4_22` is a good current GPIO/FlexIO validation pin,
but it is not a true CTIMER capture pin. Its timer function is `CT2_MAT2`,
which is a match output. For Rev B shield routing, we may keep `P4_22` and read
a free-running CTIMER counter in the GPIO ISR, or move VSYNC to a pin with a
true CTIMER capture or trigger-capable function if hardware-latched frame
timestamps become necessary.

Also recorded the exact-pin GPIO event-DMA option for later. GPIO4 has pin
event DMA request sources, so a future optimization could use a `P4_22` rising
edge to DMA-copy a free-running CTIMER count into memory for lower-jitter frame
timestamps. This is intentionally logged as a second-stage option, not the next
implementation step, because it does not replace the current CPU-side frame-DMA
setup and health/timeout handling.
