# Log: flexio-low-rate-capture

Investigated visual artifacts in the `FLEXIO_PIPELINE_DIAG` synthetic-frame LCD
test.

Finding:

The LCD dump path sends `camera_view.Data` directly to SPI with
`eGFX_DumpRaw()`. In test mode, the app also draws line-processing overlays
directly into `camera_view`. That is fine for real camera capture because the
next camera frame overwrites the buffer. It was wrong for the synthetic backend
because the diagnostic pattern was filled only once at startup, so overlay
pixels could persist when that buffer was reused.

Firmware fix:

- Stopped `avc__next_frame()` from changing `camera_view.Data` in interrupt
  context.
- The main loop now latches the current `raw_camera_frame` pointer once per
  displayed frame, assigns `camera_view.Data`, and uses that same pointer for
  line processing and LCD dump.
- Added `avc_camera__prepare_frame()`.
- For `FLEXIO_PIPELINE_DIAG`, `avc_camera__prepare_frame()` regenerates the
  selected synthetic RGB565 buffer before the test overlay draws into it. This
  makes the synthetic backend behave like a real capture source where each
  displayed frame starts from fresh camera pixels.
