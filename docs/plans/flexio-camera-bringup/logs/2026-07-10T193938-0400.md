# Log: Park FlexIO Camera Bringup

Saved the current FlexIO camera state before pausing this plan to work on other
project items.

Current status:

- FlexIO/eDMA capture is fundamentally working with the full data bus wired to
  `P4_12..P4_19`, PCLK on `P4_20`, HREF on `P4_21`, and VSYNC on `P4_22`.
- The LCD shows a live image. Remaining visual artifacts are likely wiring bit
  order or signal-integrity issues rather than a completely broken capture path.
- The active firmware is still configured for the `320x200` camera view used by
  the AVC display layout, not a confirmed `320x240` mode.
- OSTIMER-based diagnostics now measure VSYNC period, DMA-arm latency, and DMA
  frame duration without taking over SysTick.
- The latest validated RTT sample showed about `23.39 fps`, `vs_us` near
  `42,750 us`, DMA-arm latency around `16 us`, and DMA-frame duration around
  `42,410 us`.
- This frame rate matches older measurements well enough to trust the current
  instrumentation. The main performance objective when resuming is still to see
  whether the FlexIO/eDMA approach can reach the target `30 fps` where the
  SmartDMA/EZH path could not.

The plan status has been moved back to `pending` to represent an intentional
parking point. Resume with LCD/data-order cleanup, clearer diagnostic counters,
and frame-rate improvement work before making a Rev B shield decision.
