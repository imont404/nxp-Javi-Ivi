# Log: signal-instrumentation

Reran the existing `FLEXIO_DIAG` RTT diagnostic after shortening the Port 4
camera signal jumpers and adding the 330 ohm pulldown/termination treatment to
the VSYNC line. No firmware changes were made for this check.

Command:

```powershell
.\rtt.ps1 -CMake -Reset -Seconds 12
```

Observed RTT output:

- `P4_21` HSYNC/HREF counted about 6035 to 6040 rising edges per second.
- `P4_20` PCLK showed a polled edge flag during each one-second interval.
- `P4_22` VSYNC showed a polled edge flag during each one-second interval.
- Sampled Port 4 levels remained `lvl_p4=000` in the printed intervals.
- The original/reference Port 0 camera pins remained static with no edge counts
  (`lvl_ref=101`), confirming that the active diagnostic signal activity is on
  the new Port 4 wiring.

Representative line:

```text
cam_diag t_ms=5000 p4_hs=30191(+6040) p4_pclk=1 p4_vs=1 ref_hs=0(+0) ref_vs=0(+0) ref_lines=0 ref_pclk=0 lvl_p4=000 lvl_ref=101 unexp=0/0
```

This confirms that the cleaned `P4_22` VSYNC line is producing detectable
edges in the current polling diagnostic. The next firmware experiment is to
re-enable `P4_22` as a guarded GPIO interrupt source so the frame-rate count
can be measured without risking another sustained interrupt flood.
