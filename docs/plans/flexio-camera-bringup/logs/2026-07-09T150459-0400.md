# Log: flexio-low-rate-capture

Decision checkpoint after the `D0/D1` retest: pause additional data-line
wiring and prove the software frame pipeline with sync-only camera wiring.

Current hardware context:

- Stable sync wiring remains `PCLK -> P4_20`, `HSYNC/HREF -> P4_21`, and
  `VSYNC -> P4_22`.
- VSYNC is known to be sensitive to physical routing. Keeping it separated from
  the other camera signals produced the clean `30-31` edges/sec baseline.
- The latest `D0/D1` test was usable enough to keep the board running, but it
  still produced extra VSYNC edges and occasional `p4_lines` dips, so do not add
  more data lines yet.

Next firmware checkpoint:

- Add a separate sync-qualified synthetic-frame backend instead of overloading
  the existing blocking `FLEXIO_DIAG` loop.
- Keep the camera XCLK, SCCB/I2C, reset, and power-down initialization active.
- Continue using GPIO IRQs on `P4_21` HSYNC/HREF and `P4_22` VSYNC for this
  checkpoint; keep `P4_20` PCLK as activity instrumentation.
- Accept a frame only when the measured HSYNC count per VSYNC is plausible for
  the active `320x200` OV5640 mode.
- Feed alternating deterministic RGB565 test buffers into `avc__next_frame()`
  so the existing LCD and line-processing pipeline can be verified before
  FlexIO shifter/eDMA capture is added.

SysTick note:

The board has a SysTick IRQ available for future timing work, but the current
checkpoint will avoid taking ownership of `SysTick_Handler` until the existing
`e_tick` delay/timing usage is reviewed. The GPIO sync IRQ path is sufficient
for this synthetic-frame pipeline test.
