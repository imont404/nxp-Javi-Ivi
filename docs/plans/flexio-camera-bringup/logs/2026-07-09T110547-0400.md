# Log: signal-instrumentation

Added and flashed the first `FLEXIO_DIAG` firmware image for the wired sync
signals. The diagnostic backend disables SmartDMA/EZH capture, keeps the camera
sensor initialization path active, configures `P4_20`, `P4_21`, and `P4_22` as
GPIO inputs, and emits one RTT status line per second.

The first VSYNC IRQ attempt on `P4_22` produced implausible raw counts around
108k-115k rising edges per second. That is consistent with noise or termination
sensitivity on the longer VSYNC jumper, so the retained diagnostic image now
keeps P4 VSYNC as a polled rising-edge flag instead of an interrupt source.

Retained diagnostic behavior:

- `P4_21` HSYNC/HREF is counted by GPIO interrupt on `GPIO40_IRQn`.
- `P4_20` PCLK is a polled rising-edge flag.
- `P4_22` VSYNC is a polled rising-edge flag.
- The original `P0_5`, `P0_11`, and `P0_4` camera-header signals are also
  instrumented for comparison, but in this wiring state they stayed static and
  did not provide useful reference counts.

RTT after the refined flash showed:

- `P4_21` HSYNC/HREF: about 6033-6039 rising edges per second.
- `P4_20` PCLK: edge flag observed every reporting interval.
- `P4_22` VSYNC: edge flag observed every reporting interval.
- P4 sampled levels were usually `000`.
- Reference P0 sampled levels were `101` with no edge counts.

The board is currently flashed with the `FLEXIO_DIAG` image from this checkpoint.
