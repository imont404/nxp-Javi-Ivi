# Log: pin-group-selector

Pin-group selector implemented and build-validated. **Not yet flashed.**

## What changed

`CONFIG__CAMERA_FLEXIO_PIN_GROUP` added to `avc__master_config.h`, defaulting to
`CAMERA_FLEXIO_PIN_GROUP_PORT4`, with two guards: an invalid-value check, and
one rejecting the Port 1 group unless the backend is `FLEXIO_EDMA` (the older
FlexIO signal/pipeline diagnostics stay Port 4 only).

`bv_camera__interface.c` now carries per-group constants for data, PCLK, HREF,
and VSYNC, each with its own port, GPIO, clock gate, port-pin index, and
FlexIO `D` index. Naming convention kept from the existing code: `*_GPIO_PIN`
is a port bit index, `*_PIN` is a `FLEXIO0_Dnn` index.

`camera__configure_flexio_edma_pins()` no longer sweeps one contiguous pin
range on one port. It configures the eight data pins as a loop, then PCLK and
HREF explicitly, because the Port 1 group has a gap at P1_12/P1_13 and puts
HREF on a different port.

VSYNC dispatch is routed to whichever handler owns the pin. `GPIO40_IRQHandler`
now drives capture only for the Port 4 group. `GPIO00_IRQHandler` drives it for
the Port 1 group, promoting the pre-existing reference counter on P0_4 into the
capture trigger.

Shifter, timer, and eDMA configuration were **not touched** — they already read
from the FlexIO index macros, so only the constants differ between groups.

`build_flexio_camera.ps1` added: `-PinGroup Port4|Port1`, defaulting to Port4.

## Validation

| Build | text | Result |
|---|---|---|
| Default Rev A EZH | 245020 | **byte-identical to pre-change** |
| FlexIO Port 4 | 249580 | builds |
| FlexIO Port 1 | 249664 | builds |

Pin-group strings confirmed in each image:

- Port 4: `D0-D7=P4_12..P4_19/FLEXIO0_D20..D27 PCLK=P4_20/FLEXIO0_D28 HREF=P4_21/FLEXIO0_D29 VSYNC=P4_22/GPIO IRQ`
- Port 1: `D0-D7=P1_4..P1_11/FLEXIO0_D12..D19 PCLK=P1_14/FLEXIO0_D22 HREF=P0_11/FLEXIO0_D3 VSYNC=P0_4/GPIO IRQ`

Guard verified by building an invalid combination, which fails with the
intended `#error`.

## Known behaviour change, Port 1 group only

`P0_11` becomes FlexIO HREF, so the reference diagnostic's HSYNC counter stops
advancing and its lines-per-frame figure reads zero. That is expected — the pin
is being taken by FlexIO — but it means the reference diagnostic is no longer a
useful cross-check in this configuration. Noted in the handler.

## Not yet established

Nothing is flashed. `port4-regression` is still open and is the gate before
trusting any Port 1 result: the refactor touched working capture code, so the
Port 4 path must be proven on hardware first.
