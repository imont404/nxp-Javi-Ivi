# Log: rev-b-recommendation

# Plan closeout

**Objective met.** The plan asked whether the existing Rev A camera wiring could
drive FlexIO with minimal change, proving on hardware we already have that the
EZH can be released. It can, with three jumpers.

## Rev B recommendation: route it

| Signal | Rev A | Rev B |
|---|---|---|
| Camera **D4** | `P3_4` | **`P1_8`** |
| Camera **D5** | `P3_5` | **`P1_9`** |
| **PCLK** | `P0_5` | **`P1_14`** |

Nothing else moves. D0-D3 and D6-D7 are already correct, HSYNC on `P0_11`
already carries `FLEXIO0_D3`, and VSYNC on `P0_4` stays a GPIO interrupt.

That gives zero jumpers, PCLK routed properly instead of hanging off a dupont
wire, and both backends native by routing — `P1_4..P1_11` becomes contiguous
`FLEXIO0_D12..D19` *and* contiguous `SMARTDMA_PIO0..PIO7`.

Two things to settle before committing a layout:

1. **`P1_8` and MCU-Link.** `R173` (330 ohm) ties it to the VCOM TX. It caused
   no trouble — camera D4 drove the shared net cleanly through every test,
   including the EZH runs — but a respin should decide deliberately whether the
   VCOM stays on that pin rather than inherit the contention.
2. **`P1_15`** (`FLEXIO0_D23`) is the clean alternate to `P1_14` if layout
   prefers it. Avoid `P1_12` (drives Q2 on the shield) and `P1_13` (Ethernet PHY
   strap).

## Measured

| | EZH baseline | FlexIO Port 1 |
|---|---|---|
| Frame rate | 23.43 fps | **23.39 fps** |
| Frame time | ~42.7 ms | 42.42 ms |
| Errors | — | timeout 0, submit 0, callback 0, `shifterr` 00 |
| Wires | 0 as routed | **3 jumpers** |

Both backends confirmed producing a good image, flashed alternately with no
hands on the hardware.

## Closed without completing

**`ezh-freed-demo` / `ezh-available`.** Not performed. Capture running on FlexIO
is necessary but not sufficient evidence that the EZH is claimable for other
work. That demonstration belongs with whatever work actually wants the EZH,
where it can be shown doing something real rather than contrived. Recorded as an
open item in `AVC_Competition_Overview.md` rather than left as a dangling step
here.

**`port4-not-regressed`** was met on static evidence only; Port 4 remains
hardware-unverified. Carried into `build-system-cleanup` as verify-or-retire.
