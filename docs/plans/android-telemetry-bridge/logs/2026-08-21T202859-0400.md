# Log: h264-browser-proof

Implemented and verified the opt-in browser H.264 path on the Moto G Power 5G (2023) and live Rev A car. Characterized c2.mtk.avc.encoder output as Annex-B baseline avc1.42000d with separate SPS/PPS, one access unit per output, and roughly one-second IDRs. Added a minimal fragmented-MP4 muxer, AVC4 WebSocket envelope, bounded IDR-aware relay queue, MSE browser playback with bounded append queue and buffer trimming, mode-aware verification, and a reproducible relay-start helper. A final 240-fragment transport run delivered 23.067 FPS at 0.594 Mbit/s with a one-frame source/sent gap; USB held 23.422 FPS and 2.869 MiB/s with zero sequence or malformed errors. Headless installed Chrome reached readyState 4 in 469 ms, decoded a nonblack 320x200 frame, and measured 32 ms buffered-media lead. H.264 slow-client watchdog and JPEG regression both passed. JPEG remains default; H.264 is opt-in.
