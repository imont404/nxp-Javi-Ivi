# Log: Added Selectable ST7789 Panel Init

Added a compile-time display panel selector while keeping all LCD I/O unchanged.

Firmware changes:

- Added `DISPLAY_PANEL_ER_TFT020_3` and `DISPLAY_PANEL_ER_TFT020_7` in
  `src/avc/avc_core0/source/avc_config/avc__master_config.h`.
- Added `CONFIG__DISPLAY_PANEL`, defaulting to the old
  `DISPLAY_PANEL_ER_TFT020_3` path so the current display remains the default.
- Added `CONFIG__DISPLAY_TE_ENABLE`, defaulting to `0`.
- Refactored `src/avc/avc_core0/source/avc_io/st7789.c` so
  `ST7789_Initial()` dispatches to separate ER-TFT020-3 and ER-TFT020-7 command
  tables.
- Kept the same LPSPI1 data path, D/C GPIO, reset GPIO, address-window path,
  RGB565 format, and eGFX transfer functions for both panels.
- The ER-TFT020-7 path uses the vendor 4-wire SPI power/gamma command values,
  but keeps the AVC orientation and byte-order helpers so the existing
  320x240 display path is still the frame contract.

Verification:

- Default old-panel CMake build passed with `.\build_cmake.ps1 -SkipGenerate`.
- Alternate-panel CMake build passed in a separate build directory using
  `-DCMAKE_C_FLAGS:STRING=-DCONFIG__DISPLAY_PANEL=2`.

Current state:

- `spi-pin-strategy` is complete for the first SPI proof because the alternate
  panel deliberately reuses the existing LCD pins and the vendor 4-wire SPI
  straps are documented.
- `spi-bringup` is active. The next hardware-facing step is to switch
  `CONFIG__DISPLAY_PANEL` to `DISPLAY_PANEL_ER_TFT020_7`, build/flash, and
  verify a synthetic RGB565 pattern on the new display.
- EZH/bunny remains parked until after SPI validation and until the proper
  project-specific references are supplied.
