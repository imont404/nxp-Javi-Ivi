# Log: Started Parallel EZH Bunny Build Research

Started the parallel-display EZH/bunny_build research phase after the
ER-TFT020-7 worked through both the SPI RGB-band proof and the normal AVC frame
path.

Source material inspected:

  `src/common/bunny_build`
- Upstream/latest local clone:
  `C:\eli\bunny_build`
- Gibbon module copy:
  `D:\prj\teenage_engineering\lpc55_gibbon-d\gibbon-d-test-fw-west\modules\bunny_build`
- Gibbon PSRAM EZH command example:
  `D:\prj\teenage_engineering\lpc55_gibbon-d\gibbon-d-test-fw-west\app\src\ezh_app.cpp`
- ISA document:
  `C:\eli\ezh\docs\EZHandler Arch B PreRel0.6.docx`
- Public cookbook:
  `C:\eli\ezh\docs\EZH Cookbook 1.9.docx`

Findings:

- `C:\eli\bunny_build` fetched cleanly from
  `git@github.com:wavenumber-eng/bunny_build.git`; current `origin/main` is
  `9c5e8d6`.
- The gibbon module copy is also at `9c5e8d6`.
- AVC's vendored `src/common/bunny_build` is not at that latest layout. File
  comparison against `C:\eli\bunny_build` found 7 files added upstream and 13
  changed files.
- The important upstream changes are the source-refactor split:
  `include/ezh_arch.h`, `include/bunny_build__instr.h`,
  `include/bunny_build__psuedo_instr.h`, `src/bunny_build__instr.c`,
  `src/bunny_build__instr.h`, and `src/bunny_build__psuedo_instr.c`.
- The upstream `src/CMakeLists.txt` now builds `bunny_build.c`,
  `bunny_build__instr.c`, `bunny_build__psuedo_instr.c`, and `ezh_init.c`.
- AVC's generated CMake include and MCUXpresso Debug makefiles currently build
  only `bunny_build.c` and `ezh_init.c`.
- Upstream adds `include/bunny_build__config.h`; importing that file directly
  would shadow AVC's project-specific
  `src/avc/avc_core0/source/avc_config/bunny_build__config.h` because
  `bunny_build.h` includes `"bunny_build__config.h"` from its own directory
  first.
- Upstream has a naming mismatch in the pseudo-instruction API:
  `include/bunny_build__psuedo_instr.h` declares `E_END()`, but
  `src/bunny_build__psuedo_instr.c` defines `E__END()`. The gibbon example
  works around this with a local `E__END()` implementation.

EZH behavior notes:

- The cookbook says `EZHB_ARM2EZH[1:0] == 0b10` makes writes to `EZH2ARM`
  raise the ARM interrupt.
- This matches the existing AVC camera boot path, which sets
  `EZHB_ARM2EZH = param | 0x02`.
- The gibbon command pattern is a good model for LCD commands: build multiple
  EZH programs into RAM, boot a selected bounded command, write `EZH2ARM` at
  completion, then stop/hold the EZH in the ARM-side interrupt.
- The current AVC camera EZH app is different: it is event-driven, uses
  `E_ACC_VECTORED_HOLD_LV`, and lives in a forever capture loop.

Recommended next implementation slice:

1. Update AVC's vendored bunny_build to the upstream source-refactor layout.
2. Preserve AVC's project-specific bunny_build configuration, or explicitly
   adapt it so the upstream generic config does not silently take over.
3. Fix or alias the upstream `E_END`/`E__END` mismatch.
4. Update MCUXpresso/CMake source lists so the new bunny_build `.c` files are
   compiled.
5. Build the current firmware before adding any LCD EZH code.
