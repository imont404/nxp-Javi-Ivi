# Log: Added CM33 8080 Bit-Bang Proof

Implemented the CM33 baby-step proof for the ER-TFT020-7 parallel bus before
porting the transfer loop to EZH/bunny_build.

Firmware changes:

- Added `src/avc/avc_core0/source/avc_io/st7789_parallel_bitbang.c`.
- Added `CONFIG__DISPLAY_PARALLEL_BITBANG_TEST_MODE`, defaulting to `0`.
- The proof only runs when both `CONFIG__DISPLAY_TEST_MODE=1` and
  `CONFIG__DISPLAY_PARALLEL_BITBANG_TEST_MODE=1`.
- Normal committed firmware behavior remains the existing SPI/display path.

CM33 proof pin map:

- D0-D7:
  `P1_4`, `P1_5`, `P1_6`, `P1_7`, `P3_4`, `P3_5`, `P1_10`, `P1_11`.
- `WR=P0_4`.
- `RS=P0_11`.
- `CS=P4_4`, using the design-file `EZH_LCD_CS` net.
- `RST=P1_19`.
- `RD` is not MCU-driven in this slice; hold the display RD pin externally
  inactive high for the write-only proof.

Behavior:

- Uses the BuyDisplay 8-bit sample transaction order.
- Sends command bytes with `RS=0`, data bytes with `RS=1`, and one active-low
  `WR` pulse per byte.
- Sends RGB565 pixels high byte first, then low byte.
- Draws fixed red, green, and blue vertical bands.
- Emits RTT `parallel_lcd frame=` messages while repeatedly refreshing the test
  pattern.

Verification:

- Default CMake build passed with the proof disabled:
  `.\build_cmake.ps1`.
- Separate parallel-bitbang test image passed in
  `build/cmake/avc_core0-Debug-parallel-bitbang` using:
  `-DCONFIG__DISPLAY_PANEL=2 -DCONFIG__DISPLAY_TEST_MODE=1
  -DCONFIG__DISPLAY_PARALLEL_BITBANG_TEST_MODE=1`.

Next bench step:

- Power down and wire the 8080 proof bus, including `RD` inactive high.
- Flash `build/cmake/avc_core0-Debug-parallel-bitbang/avc_core0.axf`.
- Scope `WR`, `RS`, `CS`, reset, and at least one data line before judging the
  displayed RGB bands.
