# Log: Flashed Three-Band RGB Display Test

Simplified the ER-TFT020-7 display-test image to make color order and
orientation easier to validate on the bench.

Bench observation:

- The ER-TFT020-7 became active after correcting the interpretation of the
  `IM2~IM0` datasheet line. That line refers to FPC pins 3 through 5, not a
  strap value range.
- The working 4-wire SPI strap remains `IM2=VDD`, `IM1=VDD`, `IM0=GND`.

Firmware change:

- Replaced the previous moving multi-color display-test pattern with three
  fixed vertical RGB bands:
  - left third: red, RGB565 `0xF800`
  - middle third: green, RGB565 `0x07E0`
  - right third: blue, RGB565 `0x001F`
- The display-test loop still rewrites the full frame once per second and logs
  `display_test frame=N`.
- The normal firmware default remains unchanged because
  `CONFIG__DISPLAY_TEST_MODE` still defaults to `0`.

Verification:

- Default CMake build passed with `.\build_cmake.ps1 -SkipGenerate`.
- ER-TFT020-7 display-test CMake build passed in
  `build/cmake/avc_core0-Debug-er-tft020-7-test`.
- Flashed
  `build/cmake/avc_core0-Debug-er-tft020-7-test/avc_core0.axf`
  with J-Link V9.54, device `MCXN947_M33_0`, SWD at `4000 kHz`.
- J-Link programmed one `253952 bytes` flash range, verified successfully,
  reset, and released the core.
- Bench validation confirmed the display shows red, green, and blue bands from
  left to right when viewed in physical landscape orientation.

Next bench check:

- Disable `CONFIG__DISPLAY_TEST_MODE` and validate the normal AVC camera/frame
  path on the ER-TFT020-7.
