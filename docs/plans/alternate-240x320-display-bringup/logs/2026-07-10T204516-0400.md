# Log: Added Isolated SPI Display Test Mode

Added a guarded display-only test mode for the ER-TFT020-7 SPI proof.

Firmware changes:

- Added `CONFIG__DISPLAY_TEST_MODE`, defaulting to `0`, in
  `src/avc/avc_core0/source/avc_config/avc__master_config.h`.
- Added an isolated display-test path in
  `src/avc/avc_core0/source/avc_io/avc__io.c`.
- When `CONFIG__DISPLAY_TEST_MODE=1`, `avc__init()` enters the display test
  before camera, FlexIO, ADC, motor, and servo initialization.
- The test path still uses the normal `CONFIG__DISPLAY_PANEL` selector and the
  existing ST7789/eGFX/LPSPI transfer stack, so the old display remains the
  default and all LCD I/O remains unchanged.
- The synthetic test image is a full-screen RGB565 pattern with color bars,
  white border references, black diagonal references, inverted horizontal
  bands, and a one-second phase shift.
- The frame is written in 16-row chunks to avoid adding another full-size frame
  buffer just for the test.
- RTT logs include `Display test mode active: ...` and
  `display_test frame=N` messages.

Verification:

- Default committed CMake build passed with `.\build_cmake.ps1 -SkipGenerate`.
  Size report: `text=246788 data=516 bss=304148 dec=551452 hex=86a1c`.
- ER-TFT020-7 display-test CMake build passed in a separate build directory
  using `-DCONFIG__DISPLAY_PANEL=2 -DCONFIG__DISPLAY_TEST_MODE=1`.
  Size report: `text=247328 data=516 bss=314388 dec=562232 hex=89438`.

Current state:

- `spi-bringup` remains active.
- The next hardware-facing step is to flash the ER-TFT020-7 display-test image
  and verify the moving RGB565 pattern on the alternate display.
- Hardware validation is not yet claimed; the pending proof is still
  `spi-display-proof`.
