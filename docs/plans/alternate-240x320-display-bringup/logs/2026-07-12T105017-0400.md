# Log: Captured EZH 8080 Pacing Constraint

Recorded the BuyDisplay 8-bit sample write sequence and the initial EZH timing
rule for the parallel display proof.

Findings:

- The BuyDisplay `ER-TFT020-7_8BIT` sample uses 8080-style writes.
- Command writes set `RS=0`, assert `CS`, place the command byte on the data
  bus, then pulse `_WR` low/high.
- Data writes set `RS=1`, assert `CS`, and pulse `_WR` once per byte. RGB565
  pixel writes send the high byte first, then the low byte.
- The ST7789 8080 timing table gives a 66 ns minimum write cycle, 15 ns minimum
  `WRX` high/low pulse widths, and 10 ns data setup/hold.
- With EZH running instructions at 150 MHz, each instruction is about 6.67 ns,
  so an unpaced tight GPIO sequence can exceed the controller's allowed write
  rate.

Decision:

- The first EZH command/data proof should use conservative pacing through
  instruction-counted padding or `E_HEART_RYTHM_IMM` plus `E_WAIT_FOR_BEAT()`.
- Raise the write rate only after `WR`, `RS`, `CS`, and at least one data line
  are verified on the scope.
