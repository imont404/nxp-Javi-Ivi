# One-command maintainer release flow implemented

Added `src/host/release.ps1`. Its default mode builds the Release host tools,
runs the built CLI self-test, restores pinned browser-test packages with
`npm ci`, runs all host tests, rejects generated WebSerial viewer drift,
packages the runtime, verifies the outer checksum and every inner manifest
entry, extracts the archive, and reruns the CLI self-test from that extraction.

Publishing requires a clean source tree and explicit `-Publish`. The script
checks GitHub CLI authentication, a public repository with a default branch,
the repository's immutable-release setting, and the presence of the source
commit on GitHub. It rejects an existing release or remote tag, creates a
draft, downloads and verifies the uploaded ZIP, then makes the verified draft
public and verifies an anonymous download from the exact asset URL. It does
not push a branch or modify a remote. `-AllowDirty` exists only to exercise local dry runs during
development and cannot be combined with `-Publish`.

Validated locally with:

```powershell
.\src\host\release.ps1 -Version 0.0.1-test -AllowDirty -Force
```

The native build and both CLI self-tests passed. All 8 Playwright tests passed,
the generated viewer was unchanged, archive and manifest validation passed,
and the dry run explicitly stopped without upload. After reviewer hardening,
the resulting archive was 3,168,407 bytes with SHA-256
`6fb853082274228c14d41dd67313bb4910afbb5fd14675f78db6476a7eeda028`.
