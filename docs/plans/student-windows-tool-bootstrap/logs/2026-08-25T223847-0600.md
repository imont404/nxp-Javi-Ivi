# Core-tools release contract frozen

The Windows x64 student tools bundle is named
`nxp-cup-core-tools-win-x64-<version>.zip`. Version 1.0.0 is the initial
contract target. Student setup must use an exact release URL and checksum; it
must never resolve a mutable `latest` release.

The archive contains the prebuilt `nxpc_viewer.exe`, `nxpc_tool.exe`, the
pinned `rblhost.exe`, `SDL2.dll`, their required license notices, a concise
README, and a machine-readable `manifest.json`. J-Link and SEGGER binaries are
excluded: ROM-HID is the default flash path and J-Link remains an optional,
separately downloaded recovery tool.

Each archive is accompanied by an outer SHA-256 checksum file. The inner
manifest records the release version, source commit, platform and architecture,
build inputs, and the size and SHA-256 digest of every distributed file. The
archive layout is flat so setup can extract it directly into the repository's
normal host-artifact directory.

The current host package is 3,168,470 bytes (about 3.17 MB) and establishes a
realistic size budget for this release. Its runtime payload consists of the
viewer, CLI, SDL2, and rblhost; the new format replaces its timestamped name and
text manifest with the deterministic versioned contract above.

GitHub readiness was checked read-only. `gh` 2.95.0 is authenticated as
`ehughes`, the public repository `wavenumber-eng/nxp_cup` grants ADMIN access,
and the token includes `repo` and `workflow`. The remote currently has no
branches, tags, default branch, or releases. This does not block local build and
dry-run work, but it blocks publishing the first release until `main` exists on
GitHub and contains the release commit. Repository rules prohibit this plan
from pushing or changing remotes, so that publication prerequisite will be
handed to the maintainer at the publish step.
