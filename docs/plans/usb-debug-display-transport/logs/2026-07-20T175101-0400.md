# Log: avc-integration-slice

AVC USB stack integration analysis:

- This is mostly a clean middleware/config transplant plus MCUXpresso metadata, not a blind project copy.
- Copy/adapt the CDC sample USB middleware under the AVC project: usb/include, usb/device, usb/device/class, usb/phy, plus component/osa.
- Add AVC-local USB config/descriptor/application files: usb_device_config.h, fsl_os_abstraction_config.h, usb_device_descriptor.c/.h, and an AVC-specific debug stream module adapted from virtual_com.c.
- Do not copy sample board/startup/drivers/utilities wholesale. AVC already has board init, startup vectors, clocks, fsl_common, fsl_debug_console, fsl_str, and component/lists.
- Do not copy sample hardware_init.c as-is. Reuse only USB1_HS_IRQHandler, USB_DeviceClockInit, USB_DeviceIsrEnable, and optional USB_DeviceTaskFn logic in an AVC-specific USB hardware module.
- AVC startup already has weak USB1_HS_IRQHandler and the device headers expose USBHS_IRQS, so no vector table surgery is expected.
- AVC board/clock files already provide BOARD_USB_PHY_* trim values, BOARD_XTAL0_CLK_HZ, CLOCK_EnableUsbhsPhyPllClock, CLOCK_EnableUsbhsClock, kCLOCK_UsbHs, and kCLOCK_UsbHsPhy.
- Metadata required in .cproject: add usb source root; add component/osa and usb include paths; add USB_STACK_BM, OSA_USED, USE_RTOS=0. Keep AVC's __NEWLIB__ and multicore symbols. Avoid carrying sample __REDLIB__.
- The CDC sample also has MCUX_META_BUILD, MCXN947_cm33_core0_SERIES, imacros for mcux_config.h/mcuxsdk_version.h, and SDK component tags. Treat those as secondary compatibility metadata unless compile/import requires them.
- Add SDK component tags for component.osa*, middleware.usb.* and middleware.usb.phy for MCUXpresso UI/headless consistency. The scripted CMake wrapper will consume source roots/includes/defines from .cproject.
- Baseline config should explicitly define USB_DEVICE_CONFIG_USE_TASK 0 and leave USB_DEVICE_CONFIG_BUFFER_PROPERTY_CACHEABLE off, matching the measured working CDC build. Enabling cacheable buffers later needs fsl_cache/cache policy work.
- The CDC sample SDK metadata is 26.06.00 while AVC is 25.09.00. Avoid replacing AVC drivers unless the compiler proves a missing API; required HS USB clock helpers are already present.
- First AVC slice should enumerate CDC and stream synthetic frames from AVC main/service context. Then stream latest camera frames with drop-on-busy policy. Do not send from avc__next_frame() ISR context.
