# Log: usb-only-throughput-proof

Bench status before moving forward:

- The local NXP CDC VCOM sample is now the isolated USB-only test target for this plan.
- Added sample-local AGENTS.md plus build.ps1 and flash.ps1 wrappers matching the AVC workflow. The MCUXpresso headless workspace lives beside the sample tree under docs/examples/frdmmcxn947/.mcux_workspace_cdc_vcom.
- Stock CDC firmware built/flashed and enumerated on Windows as COM15 with VID_1FC9/PID_0094. A simple echo test passed.
- The sample firmware has been changed from echo-only to a synthetic AVC-sized stream: 320x200 RGB565, 128000 bytes per frame, 16 KiB TX buffer, AVCU little-endian 32-byte chunk header, START/STOP control over CDC OUT.
- Initial 5 s receiver run measured 178323456 bytes at 34.002 MiB/s, about 278 frames/s, which is well above the 5 MiB/s minimum and 8 MiB/s stretch target.
- That first run reported 4 malformed headers. The likely cause was the CDC send callback clearing the stream busy flag for non-stream endpoint completions, allowing the stream buffer to be reused before the bulk IN transfer finished. The callback has been narrowed to clear s_streamTxBusy only when epCbParam->buffer == s_streamTxBuf.

Next action: rebuild, flash, and rerun the synthetic stream test. If the framing is clean, run a longer 60 s throughput measurement and mark the throughput proof accordingly.
