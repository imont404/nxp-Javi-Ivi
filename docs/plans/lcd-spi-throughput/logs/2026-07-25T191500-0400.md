# SCK confirmed at 37.5 MHz, and the divider is already at minimum

Step `confirm-spi-clock` done for the part that can be established remotely.

## Method

`LPSPI_MasterSetBaudRate` searches for the closest achievable divider and does
not report failing to reach the request, so `CONFIG__TRANSFER_BAUDRATE` is a
wish rather than a fact. The registers hold the truth:

    SCK = srcClock / (2^PRESCALE * (SCKDIV + 2))

Added `lpspi1_get_actual_sck_hz()` and `lpspi1_report_clock()` to read
`CCR[SCKDIV]` and `TCR[PRESCALE]` back and print the result. No scope needed,
which matters because nobody is at the bench.

## Result

```
lpspi1 clock src=75000000Hz sckdiv=0 prescale=0 actual=37500000Hz requested=50000000Hz
```

- Source clock **75 MHz**, confirming PLL0 at 150 MHz through PLLCLKDIV of 2
- **`SCKDIV = 0`, `PRESCALE = 0` - the smallest divider the peripheral has**
- Actual SCK **37.5 MHz**, matching both the clock-tree derivation and the
  originally reported figure
- The requested 50 MHz was silently clamped, because it is unreachable from a
  75 MHz source

## What this settles

**There is no headroom in the LPSPI divider.** 37.5 MHz is not a misconfiguration
that a better request would fix - the peripheral is already dividing as little
as it can. The only route to a faster SCK is a faster source, which means
PLLCLKDIV, which a separate check showed is consumed by nothing but the display
driver.

So `raise-spi-clock` reduces to a single divider change with no coupling to
other peripherals, which is a far smaller and safer change than the plan
originally assumed.

## What it does not settle

Two ceilings remain, and neither can be established from here:

1. **The LPSPI module maximum** from the MCXN947 datasheet. Feeding the
   peripheral 150 MHz does not automatically license clocking SCK at 75 MHz.
2. **The panel and the wiring.** This will not fail cleanly. It shows up as
   sparkle or torn pixels while every number we can measure still looks
   perfect, so it needs someone watching the screen.

## Side note on the init argument

The measurement makes the case for a hand-written init concrete. The entire
output of `LPSPI_MasterSetBaudRate`'s 272-byte search is `SCKDIV = 0`,
`PRESCALE = 0`, and all three delay scalers were requested as 0 ns, which is
what `LPSPI_MasterSetDelayTimes` spends another 644 bytes computing. Nearly a
kilobyte of search arriving at constants that could simply be written down.
