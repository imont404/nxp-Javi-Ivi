# Log: log-channel

Implemented an opt-in bounded UTF-8 log channel without changing RTT. The public main-context API provides text and printf-style severity/category records; it returns before formatting unless a recognized session subscribes. Firmware uses eight fixed records with 15-byte categories, 160-byte text, truncation, drop/high-water counters, and at most two diagnostic packets before yielding to a pending frame. The Web viewer subscribes, validates records, and keeps a bounded 200-line console; Python validates and prints records. The first mixed test exposed duplicate packet sequences when a small transfer completed before its submit call incremented the sequence. Fixed by reserving the sequence before entering the USB driver and rolling it back only on submission failure. The corrected 10.015 s Rev A run sustained 2.875 MiB/s at 23.47 FPS, returned a four-PING burst, delivered the system log, and had zero drops, malformed packets, resyncs, sequence errors, endpoint-busy events, or send errors. Competition/USB builds, native receiver build, JS/Python checks, and 26 L0 tests pass. Browser console visual confirmation remains.
