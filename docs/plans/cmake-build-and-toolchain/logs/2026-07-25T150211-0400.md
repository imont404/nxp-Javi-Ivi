# Log: retire-mcuxpresso

**MCUXpresso is no longer required to build or flash.** Verified by observation,
not by assumption.

## What was checked

A clean configure and build of the competition preset, with the configure output
grepped for any reference to `nxp` or `MCUXpresso`:

- **Zero matches during configure.** Nothing in the build path looks for it.
- Every tool resolves to the provisioned toolchain:

```
CMAKE_C_COMPILER  out/toolchains/arm-gnu-toolchain-14.2.rel1-.../arm-none-eabi-gcc.exe
CMAKE_OBJCOPY     .../arm-none-eabi-objcopy.exe
CMAKE_SIZE        .../arm-none-eabi-size.exe
CMAKE_AR          .../arm-none-eabi-ar.exe
```

- The image is 245384 text, identical to every other competition build today,
  and the flash reported `Skipped. Contents already match` against the running
  firmware.
- It runs: `SMARTDMA_EZH`, `EZH interface configured`, servo on `P2_3/PWM1_B2`.

## What broke the dependency

Four things, each verified when it landed:

| Was | Now |
|---|---|
| Linker grouped `libcr_newlib_nohost.a`, IDE-only | `libnosys.a`, plus a bounded `_sbrk` restoring the heap limit that swap removed |
| `cr_section_macros.h` resolved from the IDE include path | vendored at `source/shared/`, listed first so the repo copy wins |
| Source list regenerated per build, needing Python and `.cproject` | committed and authoritative; regeneration is opt-in with a drift check |
| Toolchain hard-coded to `C:/nxp/...` | discovery order ending at MCUXpresso as a *fallback* |

## What MCUXpresso is still good for

Not nothing, and the documentation says so rather than pretending otherwise:

- **Changing project settings.** The `.cproject` metadata is still where source
  roots and build options are edited; `-CheckDrift` and `-Regenerate` carry the
  result into the committed source list.
- **`build.ps1`**, the headless fallback, if the CMake build ever fails in a way
  that wants the IDE to diagnose.

Neither is on the path a student walks.

## Not claimed

`student-onboarding` is still open. Everything here was verified on a machine
that *has* MCUXpresso installed — proving the build does not *use* it is not the
same as proving it works on a machine that never had it. That needs a genuinely
clean Windows box, and it is the only test that really counts.
