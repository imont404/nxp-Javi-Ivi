# Log: cmake-presets

**CMakePresets replace the wrapper scripts.** Seven presets, all building, with
the competition image as the obvious default.

```
$ cmake --list-presets
  "competition"         - Competition image (Rev A default) - START HERE
  "encoders"            - Competition image + wheel encoders
  "flexio-port1"        - FlexIO camera capture on the Rev A wiring (needs 3 jumpers)
  "flexio-port4"        - FlexIO camera capture on the original Port 4 pins (needs 11 fly-wires)
  "servo-p3-20"         - Competition image with the Rev B servo pin (P3_20)
  "encoder-diag"        - Encoder bench diagnostic, motors OFF
  "encoder-diag-motors" - Encoder bench diagnostic, MOTORS ON - car must be on blocks
```

Every preset carries a `description` explaining what it is for and what hardware
it assumes - the jumpers Port 1 needs, that the motors preset requires the car
on blocks. That is the information that used to live only in a wrapper script's
parameter list, and VS Code surfaces it in the preset picker.

## Top-level CMakeLists

Added, because presets need one source directory to point at and the firmware
CMakeLists lives three levels down. It also gives host tools somewhere to land
later - `AVC_BUILD_HOST_TOOLS` exists and currently fails with a message
pointing at this plan, so the seam is visible rather than implied.

Artifacts are forced to the top of the build directory via
`RUNTIME_OUTPUT_DIRECTORY`, so the image is `<build dir>/avc_core0.axf` whether
a preset or `build_cmake.ps1` produced it. Without that, `add_subdirectory`
buries it under `src/avc/avc_core0/`.

## Verified

- All seven presets configure and build.
- **`build_cmake.ps1` still works**, so nothing that referenced it has broken.
- The preset-built competition image is **byte-identical** to the wrapper-built
  one: flashing it reported `Skipped. Contents already match`.
- It runs on hardware - `SMARTDMA_EZH`, `EZH interface configured`, servo on
  `P2_3/PWM1_B2`.
