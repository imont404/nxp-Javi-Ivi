NXP Cup – Building the Code

This is the simple, normal path to build, program, and run the competition firmware on the FRDM-MCXN947. Type every command in a PowerShell tab in Windows Terminal, from the repository root—the folder containing setup.ps1. On a new computer, complete the Windows setup guide first.

Designed for a fast development loop. This is a modern command-line CMake and Ninja build. CMake keeps the build configuration repeatable, and Ninja recompiles only what changed. The focused terminal output is also easy to share with an AI or LLM when asking for help understanding a compiler error or troubleshooting a failed build. Review suggested changes and never share passwords, access tokens, or other private information.
Keep the car safe. Lift the driven wheels clear of the table or disconnect motor power before building and programming new code.

1. Open the project

Open the repository folder in Windows Terminal, make sure the tab says PowerShell, and open the entire folder in Visual Studio Code:

code .

2. Verify the tools

Run setup once on a new computer. It is safe to run again; verified tools are reused.

.\setup.ps1

Continue when the terminal shows Setup Complete.

3. Build the firmware

.\src\embedded\build.ps1

A successful build creates:

out\artifacts\embedded\nxp_cup_core0.bin
out\artifacts\embedded\nxp_cup_core0.axf

The BIN file is the normal ROM-HID programming image. Fix any build error before continuing. Later builds are normally faster because Ninja rebuilds only the files affected by your edits.

Normal build versus clean build

Use the normal command above for the everyday edit and build loop. It keeps the CMake configuration and lets Ninja rebuild only what changed. Use a clean build when you moved a repository that already contained an out\build cache, changed compilers, or suspect stale build state:

.\src\embedded\build.ps1 -Clean

A fresh clone does not require -Clean; its first normal build has no previous cache.

4. Connect the board through J11

  1. Connect one FRDM-MCXN947 to the PC through J11.
  2. Wait a few seconds for Windows to detect it.
  3. Close the viewer or any serial terminal already using the board.

5. Flash from Windows Terminal

.\src\embedded\flash.ps1

This command uses the installed nxpc_tool.exe host tool. It asks the running firmware to enter ROM-HID safely, validates the BIN file, erases, writes, verifies, resets, and waits for the application to reconnect. Do not unplug the USB cable while programming is in progress.

The happy path finishes with program=ok. J-Link is not required.

6. Open the viewer

.\out\artifacts\host\nxpc_viewer.exe

The viewer shows camera frames and telemetry after the board reconnects.

Program from the host viewer

The generated firmware normally lives here:

out\artifacts\embedded\nxp_cup_core0.bin

If the firmware field is blank or points somewhere else, click Browse and select that BIN file. Then:

  1. Build the firmware first.
  2. Confirm that the Program firmware panel shows the BIN above.
  3. Click Program and reconnect.
  4. Wait for Programming complete; preview reconnected.
No buttons are needed for a normal update. The running NXP Cup firmware accepts a boot-entry command from the host and restarts into ROM ISP automatically. Use the SW3 plus SW1/RESET recovery sequence only when no valid firmware is running, or when the loaded firmware cannot accept that command.

Use either the viewer button or flash.ps1 for a programming run, not both at the same time.

Normal edit, build, and flash loop

# Edit test_mode.c or race_mode.c in Visual Studio Code
.\src\embedded\build.ps1
.\src\embedded\flash.ps1

If the happy path fails, use the setup and troubleshooting guide for permissions, connection checks, and physical ROM recovery.
