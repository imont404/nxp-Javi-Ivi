NXP Cup – Student Setup

This is the authoritative Windows setup, build, flash, and viewer guide. Run every command below from the repository root—the folder containing setup.ps1.

Keep the car safe while setting up. Lift the driven wheels clear of the table or disconnect motor power. The framework owns safety stops, but new code should never get its first test with the car free to move.

1. Before you start

  • Use 64-bit Windows 10 or 11.
  • Keep at least 2 GB of disk space free.
  • Use Windows PowerShell in a normal, non-administrator terminal.
  • Have internet access for the first setup, unless your instructor supplied the offline archives.
  • Use a USB cable that carries data, not a charge-only cable.

PowerShell permission

First try:

.\setup.ps1

If Windows says that running scripts is disabled, permit it only in the current PowerShell window:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup.ps1
This is temporary. It does not require administrator access and ends when that PowerShell window closes. Do not change the machine-wide policy to Unrestricted. If school Group Policy or application control still blocks the script, stop and ask the instructor or IT staff rather than trying to bypass the managed policy.

winget may show a normal Windows installer or UAC prompt for CMake or Ninja. On a managed laptop, winget may be disabled entirely; see Permissions and managed laptops below.

2. Run setup

.\setup.ps1

The first run installs and verifies:

ItemPurposeLocation
Arm GNU Toolchain 14.2.Rel1Build the MCXN947 firmwareout\toolchains
CMake and NinjaConfigure and run the firmware buildInstalled through winget if missing
Core tools 1.0.0Viewer, command-line tool, and ROM-HID programmerout\artifacts\host

The Arm download is 305 MB and extracts to about 1.2 GB. Setup shows download and extraction progress. Verified downloads are retained under out\downloads, so later runs are fast and normally use no network.

Setup checks exact versions and SHA-256 hashes, validates every file in the host package, and runs the host self-test before replacing a working install. Do not work around a checksum failure.

Ordinary students do not need Visual Studio, LLVM, Rust, MCUXpresso, Ozone, or J-Link. Maintainers rebuilding the Windows viewer from source can run .\setup.ps1 -IncludeMaintainerTools separately.

3. Build the competition firmware

.\src\embedded\build.ps1

A successful build publishes:

  • out\artifacts\embedded\nxp_cup_core0.bin — normal ROM-HID programming image
  • out\artifacts\embedded\nxp_cup_core0.axf — debugger image with symbols

The two normal student files are:

src\embedded\nxp_cup_core0\source\app\test_mode.c
src\embedded\nxp_cup_core0\source\app\race_mode.c

If a previous build remembered another compiler or behaves unexpectedly, make one clean build:

.\src\embedded\build.ps1 -Clean

4. Connect and flash through J11

  1. Connect the FRDM-MCXN947 J11 USB port to the PC with a data cable.
  2. Wait a few seconds for Windows to enumerate the board.
  3. Close any other program using the board's serial port.
  4. Run:
.\src\embedded\flash.ps1

The preferred path asks a running competition application to stop safely and enter the MCXN947 ROM-HID bootloader. It then validates, erases, writes, resets, and waits for the application to reconnect. J-Link is only an optional maintainer fallback.

Physical ROM recovery

If the application is broken and cannot enter ROM automatically:

  1. Leave the J11 USB cable connected.
  2. Press and hold SW3.
  3. Press and release SW1 / RESET.
  4. Release SW3.
  5. Force the ROM path so its error remains visible:
.\src\embedded\flash.ps1 -Backend Rom

This recovery does not require J-Link. After programming, the board should reset and return as the normal NXP Cup USB device.

5. Open the viewer

.\out\artifacts\host\nxpc_viewer.exe

The viewer connects to one NXP Cup board, negotiates telemetry, and displays camera frames and named values. Its firmware field automatically finds the BIN produced by the normal build. If several matching boards are connected, remove the extras rather than guessing which one will be programmed.

Normal work loop

# Edit test_mode.c or race_mode.c
.\src\embedded\build.ps1
.\src\embedded\flash.ps1
.\out\artifacts\host\nxpc_viewer.exe

Potential problems

Permissions and managed laptops

  • Scripts are disabled: use the process-only execution-policy command in step 1.
  • Group Policy, AppLocker, or antivirus blocks the script or downloaded executables: ask the instructor or IT staff to approve this repository and its pinned vendor tools. Do not disable organization security controls.
  • winget is missing or blocked: CMake and Ninja must be installed by IT or the instructor. Rerun setup afterward; it will verify both commands.
  • UAC appears: confirm that the prompt names the expected CMake or Ninja installation. Cancel unexpected prompts.

Download or checksum failure

  • Confirm that the PC can reach developer.arm.com and github.com through its proxy or firewall.
  • Rerun setup after an interrupted download; incomplete .partial files are not accepted as cache entries.
  • Use .\setup.ps1 -Force only when you intentionally want to redownload the pinned archives.
  • Never edit the expected hashes or use an archive that setup rejects.

The board is not found

  • Confirm the cable is connected to J11 and supports data.
  • Disconnect extra NXP Cup boards.
  • Close the viewer, serial terminals, and other programs that may own the port.
  • Unplug J11, reconnect it, and wait for Windows enumeration.
  • If the application no longer runs, use the physical ROM recovery sequence above.
  • If the default flash command complains that J-Link is missing, recover with -Backend Rom; J-Link is not required for the student path.

Setup was interrupted

Run .\setup.ps1 again. Setup validates staging and cache contents before installation and does not replace a known-good host runtime with an incomplete candidate.

Offline archives

An instructor can provide the exact pinned Arm and core-tools ZIP files. Use:

.\setup.ps1 `
  -ArmArchive D:\NxpCup\arm-gnu-toolchain-14.2.rel1-mingw-w64-i686-arm-none-eabi.zip `
  -CoreToolsArchive D:\NxpCup\nxp-cup-core-tools-win-x64-1.0.0.zip

The same checksum and package validation applies offline. CMake and Ninja must already be installed when winget cannot reach its sources.
